# TasteBridge — submission draft

**Tagline:** Different tastes. One movie night. A shortlist with visible trade-offs.

**Inspiration:** Groups compromise without knowing how a proposed film relates to each person's tastes. TasteBridge combines confirmed movie/artist seeds into a transparent shortlist.

**What it does:** Two to four friends explicitly select Qloo entities. A bounded native Workers AI planner uses staged `recommend_for_group`, `rank_for_group` and `refine_preferences` tools. The server retrieves up to twenty candidates per member, reuses duplicate retrievals and equally combines average/minimum candidate-rank utilities. It displays up to three films with returned metadata and visible trade-offs. Three successful exact seen-film exclusions are supported. Version checks prevent stale publication; failed updates preserve only a valid same-version shortlist.

**Qloo use:** Official hackathon `/search` disambiguates movie/artist seeds; `/v2/insights` returns film candidates. Only returned metadata/rank evidence is displayed, with retrieval timing. Missing rank means missing evidence, not dislike. Qloo supplies taste data; the model supplies bounded planning. Captured returned data is not bundled or published in source under the [developer guide](https://docs.qloo.com/reference/qloo-llm-hackathon-developer-guide).

**Built with:** React/React DOM, TypeScript, Vite, Qloo Taste AI, Cloudflare Workers, Static Assets, native Workers AI and D1. The public app uses Workers Free and `@cf/meta/llama-3.3-70b-instruct-fp8-fast`. D1 stores sessions, versioned groups, recommendation runs, shared leases, compact private cache entries and physical-request quota claims. The original Python/FastAPI/HTTPX/Pydantic/SQLite application remains a local alternative with official Codex CLI and an eligible ChatGPT login; it is not the hosted runtime. No payment card, additional spending or paid fallback is authorized.

**How it was built:** The frontend separates confirmed preferences, the group shortlist and inspectable rank evidence. The server independently validates every model plan, offers only the current workflow stage and authorizes exact seen IDs from the current group's shown results. Parameterless retrieval/ranking stages constrain model arguments to `{}` and one proposed call. A one-MiB response guard and complete secret-reflection checks precede compact projection of the seven card fields; oversized/mistyped optional values are omitted without replacement data. Versioned D1 publication preserves a valid prior shortlist after failed refinement.

**Bounds:** Four model attempts/eight tools per run. Native AI allows 20 seconds per request, a 6,000-byte complete JSON input and 1,024 output tokens, with no automatic model retry. D1 caps 100 model / 500 physical Qloo calls per UTC day, including failures/retries. Shared leases allow two active recommendation workflows and two Qloo calls. Sessions/results expire after 24 hours; groups support three successful seen updates. Free-account quotas may stop requests sooner. No claim of unlimited or guaranteed Free availability is made.
