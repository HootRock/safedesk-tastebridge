# TasteBridge limitations

- Group score uses up to twenty returned candidates per member, equally combining average/minimum rank utility. It is not a probability; missing rank is not dislike. Only up to three group films are shown.
- Movie/artist seeds require explicit confirmation. No private profile ingestion, bookings, payments, automatic preference creation or invented entities are supported.
- Explanations may be absent. Available rank evidence is shown without generated taste claims. Natural-language feedback supports shown-film exclusions; vague genre/tone requests require clarification.
- Qloo responses are bounded to one MiB. Only seven card metadata fields are cached/persisted: release year, duration, rating, genres, image URL, plot summary and description. Invalid or oversized optional values are omitted, so some genuine long descriptions may be unavailable. Complete literal/decoded secret-reflection checks apply before projection. No captured Qloo response dataset ships in source; live metadata/posters retain their third-party terms and hosts can be unavailable.
- Private recommendation cache entries last less than fifteen minutes, with at most 256 entries in D1. Shared D1 leases allow two active recommendation workflows and two active Qloo requests; limits can reject concurrency. Sessions/results expire after 24 hours. Reloaded favorites must be confirmed again; the group uses version checks.
- Four run attempts are allowed per session in ten minutes, including failures. Each group supports three successful exact seen updates; an additional update is rejected by the server. Failed updates retain only a valid same-version shortlist and do not publish partial candidates.
- Native Workers AI requests have a 20-second deadline, 6,000-byte complete JSON input cap including schemas/history, 1,024 completion tokens and no automatic model retry. Large inputs fail without truncating evidence. The Promise deadline cannot cancel an already dispatched native model operation; its physical quota remains consumed and late output is ignored. Each workflow permits four model attempts and eight tools. A 210-second Agent operation budget stops further tool work; awaited final storage/lease cleanup can extend the HTTP response beyond it.
- D1 enforces 100 model / 500 physical Qloo calls per UTC day, including failed calls and Qloo retries. Free-account compute, CPU, storage and provider quotas can stop access sooner; 100 successful calls and continuous judging access are not guaranteed. The selected runtime is Cloudflare Workers Free, Static Assets, native Workers AI and D1. No payment card, additional spending, paid fallback or upgrade is authorized.
- Local Codex uses eligible subscription allowance, a 90-second planner request deadline and local-only authentication. The original Python application and earlier Groq/Render/Turso hosting alternatives remain in source; they are not the selected public runtime. Render required card verification and was not selected.
- As of **2026-10-09**, current Worker source passed 146 offline tests in eight files, typecheck and dry packaging. [Public CI](https://github.com/HootRock/safedesk-tastebridge/actions/runs/37921112133) passed backend, frontend and Worker jobs; an independent copy matched all 152 expected public-source files by SHA-256. The Python baseline passed 216 tests / one live test deselected, and frontend checks passed 84 tests plus typecheck/build. These checks use synthetic provider data.
- The [public app](https://tastebridge-hackathon.wtr1274970944.workers.dev/tastebridge), D1 migration, bindings, encrypted Production Qloo secret and root redirect are verified. Actual live two-member search, an initial twenty-films-per-member recommendation and all three successful exact seen exclusions completed. Earlier model-validation failures preserved the previous shortlist and a later retry succeeded. A `Live · hosted` badge alone does not establish provider success.
- Real four-member recommendations, independent-session isolation, concurrency/capacity, long-lived availability and complete CPU/D1 behavior have not all been measured live. A fully wired synthetic four-member workflow with physical Qloo retries used 41 D1 statements including run/group reads; it is offline evidence. The current active-version metric sample showed six invocations and zero errors, a 5 ms CPU summary and a recent CPU p99/p999 bucket of 142 ms, without a recorded CPU-limit rejection. This does not establish that each complete request stays within the Workers Free CPU allowance. Build startup timing and local synthetic benchmarks are not live CPU evidence.
